# قوالب Prompts (مأخوذة من صيغ طلباتك الفعلية)

## 1) Fix + Verify (من الـ audit)
```
أريد FIX + VERIFY فقط، وليس redesign.
الـ Art Direction الحالي: <…> — ممنوع تغييره.
المشاكل:
 1. <الوصف المرئي> — على <عرض>. لا تفترض السبب: تحقق بنفسك.
    يجب الحفاظ على: <…>   ممنوع: <…>
 2. …
ممنوع المساس: <Supabase/Admin/Tracking/IDs/…>
سير العمل: INSPECT → ROOT CAUSE → FIX → TEST → VERIFY VISUALLY → REPORT.
القبول: لقطات <قائمة> ديسكتوب 1440 وموبايل 390، لا overflow، لا أخطاء console، بيانات حقيقية.
التقرير (بالعربي): السبب الجذري لكل مشكلة، الملفات، التغييرات، كيف اختُبر، ما لم يُختبر.
```

## 2) Refinement (من L325)
```
هذه مرحلة Refinement/Visual Polish، مش إعادة تصميم. عدّل النقاط المحددة فقط.
حافظ على: <قائمة>. لا تغيّر: <قائمة الأقسام المحمية — بالاسم>.
[لكل نقطة] المشكلة الحالية / المطلوب / لا نريد.
اختبر ديسكتوب وموبايل (wheel حقيقي + touch).
```

## 3) اتجاهات تصميم (من L2220)
```
حاسس إن النتيجة <عادية/مش عاجباني> ومش عارف أوصف ليه.
اعمل 3 اتجاهات مختلفة جذريًا كـ mockups حقيقية (HTML على بيانات الموقع الفعلية)، مش وصف.
بعد ما أختار: لوحتين ألوان للاتجاه المختار، ثم نفّذ.
```

## 4) سؤال جدوى
```
ينفع نعمل <فكرة>؟ قل: ممكن/مش ممكن، القيود، وإيه اللي محتاجه مني. بعدها أقرر.
```

## 5) تعميم
```
طبّق الاتجاه على: <كل الأسطح: صفحات، لوحة تحكم، منيو موبايل، 404>. اعمل جرد الأول وورّيني القائمة.
```

## 6) تتبّع إعلانات
```
اتأكد إن كل CTA (واتساب/اتصال/سلة) في <كل الصفحات> ليه حدث <منصة>. قولي إيه اللي اتأكد منه وإيه اللي لازم أختبره أنا.
```
